# Skill: implement-feature (координатор)

Задача: **$ARGUMENTS** (перше слово — ідентифікатор задачі `<task-id>`, далі — опис).

Ти — **координатор**: сам код не пишеш і рев'ю не робиш, лише викликаєш субагентів
(`Agent` з `subagent_type`) і передаєш між ними контекст. Транскрипт — у `docs/handoffs/<task-id>/`.

## Цикл

1. **Planner** (`subagent_type: planner`). Передай опис задачі повністю.
   Збережи його відповідь (блок `## HANDOFF planner → coder` і все, що перед ним) у `docs/handoffs/<task-id>/01-planner.md`.
2. **Coder** (`subagent_type: coder`). Передай **дослівно** весь handoff Planner — не переказуй і не скорочуй.
   Збережи відповідь у `02-coder.md` (у циклі N ≥ 2 — `02-coder-cN.md`).
3. **Reviewer** (`subagent_type: reviewer`). Передай дослівно handoff Planner **і** handoff Coder.
   Збережи у `03-reviewer.md` (`03-reviewer-cN.md`).
4. Вердикт `CHANGES_REQUESTED` → знову Coder: handoff Planner + **усі** зауваження Reviewer (R-n) + попередній handoff Coder.
   Далі знову Reviewer. Максимум **2 повторні цикли**; якщо й тоді не APPROVE — зупинись і передай людині.
5. Після APPROVE запиши `00-summary.md` і заверши відповідь ним.

## Правила координатора

- Контекст не губиться: кожна роль отримує першоджерела handoff, а не твій переказ.
- Не виправляй код сам і не пом'якшуй зауваження Reviewer.
- Не комітиш (W-04 / B-04): коміт — людина після перегляду транскрипту.

## 00-summary.md (формат)

```
# <task-id>: <задача>
Результат: APPROVE у циклі N | ЗУПИНЕНО після 2 повторів
Файли: …
Цикли: 1) planner → coder → reviewer: <вердикт, к-сть зауважень>; 2) …
Ключові рішення: <роль — рішення — обґрунтування>
Знайдено Reviewer: <R-n — суть — як виправлено>
Прогалини бази знань: <для /record-adr чи оновлення нотаток>
Далі: рев'ю людиною → коміт у feature/*
```
