# Skill: generate-tests (цільова задача T-02)

Згенеруй тести для модуля **$ARGUMENTS**. Тести перевіряють не «як написано код», а **правила
з бази знань** — саме нотатки vault є специфікацією очікуваної поведінки.

## Процедура

1. **Прочитай модуль** (`Read`). Випиши експортовані функції, їхні параметри й типи.
2. **Знайди специфікацію в базі знань** (лише через MCP `fridge-kb`, B-02):
   - `search_notes` за назвою файлу / функцій, `type: component` → нотатка компонента, чиє поле `path` збігається з модулем;
   - `get_note` компонента → `relations.outgoing.implements` — концепції, які він реалізує;
   - `get_note` кожної концепції → правила, формули, таблиці значень, розділ «Граничні випадки»;
   - `relations.incoming.governed_by` → ADR з обмеженнями (наприклад, ADR-0003: поточна дата — параметр).
   Якщо нотатку не знайдено — зупинись і повідом; не вигадуй правил.
3. **Склади перелік тест-кейсів** до написання коду: кожне правило з нотатки → щонайменше один тест;
   кожен граничний випадок → окремий тест; некоректні входи (якщо функція їх валідує) → тест на виняток.
4. **Перевір guardrails перед записом** (`docs/guardrails.md`):
   - файл тестів — лише `packages/<пакет>/test/<модуль>.test.ts` (A-06); не в `src/domain/` (W-01);
   - **не змінюй код модуля**: якщо тест показує розбіжність коду з нотаткою — залиш тест, познач розбіжність у звіті (зміна доменного ядра — W-01, рішення за людиною);
   - без `.only`, `.skip`, `@ts-ignore`, `@ts-nocheck` (B-09); без читання `.env` (B-01);
   - без `Date.now()` і моків часу — дати передаються явно.
5. **Напиши тести** за шаблоном і конвенціями з [test-conventions.md](test-conventions.md).
6. **Запусти** `npx vitest run test/<модуль>.test.ts` у теці пакета, потім з `--coverage`.
   - Тест упав через помилку в самому тесті → виправ тест і запусти знову (до 3 спроб).
   - Тест упав, бо код суперечить нотатці → не виправляй ні код, ні очікування; познач як розбіжність.
7. **Не комітиш**: коміт робить людина після рев'ю (W-04, B-04).

## Формат результату

Відповідь завершується звітом рівно в такому форматі:

```
## Звіт generate-tests
Модуль: <шлях>
Файл тестів: <шлях> (<N> тестів у <M> групах)
Специфікація: <нотатки vault через кому>
Результат: <passed>/<total> passed; покриття модуля: lines <x>%, branches <y>%
Розбіжності код ↔ база знань: <немає | перелік з посиланням на правило нотатки>
Неоднозначності специфікації: <немає | що довелося вирішити самостійно і як>
Guardrails: A-06 (тести в test/), B-09 (без .only/.skip), код модуля не змінено
Далі: рев'ю людиною → коміт у feature/* (W-04)
```
