# Конвенції тестів проєкту

## Розміщення й іменування

- `packages/<пакет>/test/<модуль>.test.ts` — один файл на модуль `src/domain/<модуль>.ts`.
- Імпорт тестованого коду — з `../src/domain/<модуль>.js` (ESM, розширення `.js`).
- Імпорт API Vitest явно: `import { describe, it, expect } from 'vitest';` (глобальні змінні вимкнено).

## Структура

- Верхній `describe` — назва функції; вкладені `describe` — правило з нотатки, у назві посилання
  на джерело: `describe('Статус свіжості: expiring, якщо 0 ≤ daysLeft ≤ 3', …)`.
- Назва `it` — сценарій українською у формі «вхід → результат»: `it('expiresAt = сьогодні → expiring', …)`.
- Однотипні випадки — таблицею `it.each`:

```ts
it.each([
  ['2026-10-26', 'expiring'], // сьогодні, 0 днів
  ['2026-10-29', 'expiring'], // +3 — межа
  ['2026-10-30', 'fresh'],    // +4
  ['2026-10-25', 'expired'],  // учора
] as const)('expiresAt=%s → %s', (expiresAt, expected) => {
  expect(getFreshnessStatus(expiresAt, TODAY)).toBe(expected);
});
```

- Arrange–Act–Assert; одна поведінка на тест; фікстури — константи на початку файлу (`const TODAY = '2026-10-26'`).
- Винятки: `expect(() => f(bad)).toThrow(RangeError)`.
- Для ранжування — перевіряти **точний порядок** ідентифікаторів і числові поля (`toEqual`), а не лише довжину.

## Заборонено

- `.only`, `.skip`, `.todo` у закомічених тестах; `@ts-ignore`; `any` без потреби.
- Залежність від поточної дати, часового поясу машини, мережі, файлової системи.
- Перевірка деталей реалізації (приватних функцій, порядку викликів) замість поведінки з нотаток.
