# ЗАВДАННЯ

## Застосунок

**«Що в холодильнику»** — веб-застосунок для обліку продуктів у холодильнику,
морозилці та коморі, контролю термінів придатності й підбору рецептів з наявних
продуктів.

**Цільові користувачі:** власники домогосподарств, студенти та люди, що живуть
самі, — усі, хто хоче менше викидати їжі й не купувати зайвого.

**Функціональні вимоги** (детально — [docs/app-requirements.md](docs/app-requirements.md)):

1. FR-01 — облік продуктів (додавання, редагування, видалення; кількість, місце зберігання, термін придатності).
2. FR-02 — пошук, фільтрація та сортування продуктів.
3. FR-03 — контроль термінів придатності: статуси `fresh` / `expiring` / `expired`, список «Скоро зіпсується».
4. FR-04 — каталог рецептів із seed-набором.
5. FR-05 — підбір рецептів за наявними продуктами з пріоритетом продуктів, що скоро зіпсуються.
6. FR-06 — «Приготувати» рецепт зі списанням продуктів.
7. FR-07 — список покупок із відсутніх інгредієнтів.
8. FR-08 — реєстрація та вхід, ізоляція даних користувачів.
9. FR-09 — журнал подій і статистика спожитого / викинутого.
10. FR-10 — імпорт / експорт продуктів у JSON.

**Технологічний стек:** TypeScript; React 19 + Vite (фронтенд); Node.js 24 LTS +
Express + zod (API); SQLite + Prisma; Vitest, Supertest, React Testing Library;
ESLint, Prettier; монорепозиторій npm workspaces.

## Обрана агентна IDE

**Claude Code** (CLI + розширення VS Code). Нативно підтримує всі механізми,
потрібні курсу: MCP-сервери (`.mcp.json`), виконання bash-команд, проєктні
інструкції (`CLAUDE.md`), hooks (`PreToolUse` / `PostToolUse` та ін. у
`.claude/settings.json`), правила дозволів allow / ask / deny, skills
(`.claude/skills/`) і subagents (`.claude/agents/`). Уся конфігурація harness
зберігається файлами в репозиторії та версіонується разом із кодом.

## Мета harness

Прискорити створення однотипних модулів застосунку, тестів і документації агентом
Claude Code, забезпечивши: доступ агента до актуальних знань про проєкт через
окремий репозиторій бази знань (Obsidian vault) і MCP-конектор; повторювані
процедури як skills; захист коду, історії git, БД і самого harness від
помилкових автономних дій через guardrails; вимірювання надійності роботи агента.
Детально — [docs/harness-requirements.md](docs/harness-requirements.md).

## Цільові задачі агента

1. **T-01 Генерація каркасу модуля** — вертикальний зріз сутності (zod-схема → Prisma → repository / service / router → React-хук і сторінка) за прийнятою архітектурою.
2. **T-02 Генерація unit- та інтеграційних тестів** — Vitest / Supertest для нової функціональності з граничними випадками.
3. **T-03 Рев'ю коду за конвенціями проєкту** — перевірка diff за чек-листом перед комітом.
4. **T-04 Синхронізація документації і бази знань** — оновлення OpenAPI, README та нотаток vault після змін коду.
5. **T-05 Аналіз збоїв тестів і збірки** — визначення першопричини та мінімальне виправлення.
